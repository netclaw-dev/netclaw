# Self-Diagnostics

<!-- description: How to check Netclaw configuration, validate connectivity, inspect logs, and troubleshoot issues -->

## Quick Reference

| What | Command / Path |
|------|---------------|
| Offline config validation | `netclaw doctor` |
| Daemon status (requires daemon) | `netclaw status` |
| Daemon lifecycle | `netclaw daemon start\|stop\|status` |
| Health endpoint | `curl http://127.0.0.1:5199/api/health/ready` |
| Full status JSON | `curl http://127.0.0.1:5199/api/health/status` |
| Active sessions | `curl http://127.0.0.1:5199/api/sessions` |
| MCP server status | `netclaw mcp list` |
| Provider list | `netclaw provider list` |
| Model configuration | `netclaw model list` |
| Discover available models | `netclaw model discover <provider>` |

## Configuration Files

| File | Purpose |
|------|---------|
| `~/.netclaw/config/netclaw.json` | Base configuration (providers, models, tools, sessions, memory, MCP) |
| `~/.netclaw/config/secrets.json` | Credentials overlay (API keys, tokens) |

Use `file_read` to inspect these files. **Never log or display API keys.**

Config layering (lowest → highest priority):
1. `netclaw.json`
2. `secrets.json`
3. `NETCLAW_` environment variables

**Config hot-reload:** The daemon watches `netclaw.json` and `secrets.json` for
changes. On a valid config change, it automatically restarts (500ms debounce).
Invalid JSON is rejected with a warning — no restart occurs.

## netclaw doctor

Primary offline diagnostic tool. Runs without a daemon.

```bash
netclaw doctor                # text output
netclaw doctor --format json  # machine-readable
netclaw doctor --fix          # auto-fix what it can
netclaw doctor --fix --dry-run  # show what --fix would do
```

Checks: config schema validation, Slack ACL, telemetry endpoint, secrets.json
syntax, Slack API auth, MCP server connectivity, context window configuration.

Exit codes: 0 = all pass, 1 = errors, 2 = warnings only.

## Daemon Lifecycle

```bash
netclaw daemon start    # start daemon in background
netclaw daemon stop     # graceful shutdown (SIGTERM, 10s timeout)
netclaw daemon status   # check if daemon process is alive
netclaw daemon install  # register as systemd user service
netclaw daemon uninstall
```

PID file: `~/.netclaw/netclaw.pid` (two lines: PID and ISO-8601 start time).

The daemon endpoint defaults to `http://127.0.0.1:5199`. Override with
`NETCLAW_DAEMON_ENDPOINT` env var or `Daemon:Endpoint` in config.

## Logs

| Log | Location | Notes |
|-----|----------|-------|
| Daemon | `~/.netclaw/logs/daemon-{yyyy-MM-dd}.log` | Daily rotation, 10MB size limit |
| Session | `~/.netclaw/logs/sessions/{yyyyMMdd-HHmmss}_{session-id}.log` | Per-session, sorted newest-first |
| Crash | `~/.netclaw/logs/crash-{yyyyMMdd-HHmmss}.log` | Written on unhandled exceptions |

Enable console logging: set `"Logging": { "Console": { "Enabled": true } }` in
`netclaw.json`.

Use `file_read` to inspect log files when debugging issues.

## MCP Server Management

```bash
netclaw mcp list               # show all servers with live status
netclaw mcp add <name> [url]   # add a new MCP server
netclaw mcp get <name>         # show server details
netclaw mcp remove <name>      # remove a server
netclaw mcp enable <name>      # enable a disabled server
netclaw mcp disable <name>     # disable without removing
netclaw mcp auth <name>        # start OAuth flow for HTTP servers
```

MCP states: `Connected` (healthy), `Disabled`, `Error`, `AwaitingAuth` (needs
`netclaw mcp auth <name>`).

## Common Issues

| Symptom | Check |
|---------|-------|
| No LLM responses | `netclaw doctor` — verify provider API key in secrets.json |
| Missing tools | `netclaw mcp list` — check server status and daemon logs |
| Slow responses | `netclaw model list` — check model size; `netclaw model discover <provider>` for alternatives |
| Session not persisting | Check `Persistence` section in netclaw.json (default: SQLite at `~/.netclaw/netclaw.db`) |
| Daemon won't start | Check for stale PID file at `~/.netclaw/netclaw.pid`; check crash logs |
| Config changes not taking effect | Verify JSON syntax is valid (daemon rejects invalid JSON silently) |
| MCP server needs auth | Run `netclaw mcp auth <name>` to complete OAuth flow |
| Model capabilities unknown | Run `netclaw model discover <provider>` or set `ContextWindow` manually |

## Reporting Bugs

File issues at the project's GitHub repository. Include:
- Netclaw version (`netclaw --version`)
- Relevant log excerpts (redact API keys)
- `netclaw doctor --format json` output
- Steps to reproduce
- Expected vs actual behavior
