## 3. DeliverTrustedSessionTurn protocol + Slack gateway handler

- [ ] 3.1 Add `src/Netclaw.Actors/Protocol/Commands.cs` new record `DeliverTrustedSessionTurn(SessionId SessionId, string Content, MessageSource Source) : IWithSessionId`. No channel specifics; lives in the shared protocol namespace.
- [ ] 3.2 **Slack side**: factor the existing `SlackGatewayActor` inbound routing (conversation lookup-or-create, thread binding lookup-or-create) into a shared private helper so the `SlackInboundMessage` handler and a new `DeliverTrustedSessionTurn` handler can share it.
- [ ] 3.3 **Slack side**: add `Receive<DeliverTrustedSessionTurn>` handler on `SlackGatewayActor`. Read `Sender` (the caller's `Ask` temp actor) and store it for the duration of the handler. Parse `SessionId` → `(SlackChannelId, SlackThreadTs)`. Run the shared lookup-or-create helper to reach the thread binding actor. Tell the binding a new internal `SlackTrustedInbound(content, source, ackTarget)` where `ackTarget = Sender`. **Do NOT reply to the Ask directly on the happy path** — the reply will flow back from the `LlmSessionActor`'s `TryReplyAck` through `ChannelPipeline`'s sender propagation. Reply `CommandNack` directly only if the binding actor cannot be reached (Tell fails) or if the offer path reports backpressure/failure. Skip `SlackAclPolicy.EvaluateInbound` — the provenance flags on `Source` indicate this is a trusted delivery.
- [ ] 3.4 **Slack side**: add `SlackTrustedInbound` handler on `SlackThreadBindingActor`. Validate that the session ID matches the binding's thread. Construct a `ChannelInput` carrying the content, the supplied `MessageSource`, and `AckTarget = the supplied ackTarget ref` (the original Ask temp actor propagated from the gateway handler). Offer it to the pipeline queue via `inputQueue.OfferAsync`. If the offer returns a non-`Enqueued` result, the binding SHALL Tell the `AckTarget` a `CommandNack` directly so the execution child's Ask can complete with failure; otherwise do not reply (the session's `TryReplyAck` will fire the `CommandAck`).
- [ ] 3.5 **SignalR side**: factor the existing `SessionRegistry.StartSignalRSession` lookup-or-create flow (knownSessions dictionary, connection binding, `SignalRGatewayActor ! StartSignalRSession`) into a shared helper so both `StartSignalRSession` (inbound from hub) and a new `DeliverTrustedSessionTurn` handler can share it. Note: the trusted-delivery handler does NOT bind a `SignalRConnectionId` — reminders have no inbound connection.
- [ ] 3.6 **SignalR side**: add `Receive<DeliverTrustedSessionTurn>` handler on `SignalRGatewayActor` (or the appropriate actor in `src/Netclaw.Daemon/Gateway/`). Read `Sender` at the top of the handler. Parse `SessionId` → `signalr/{guid}`. Run the shared lookup-or-create helper to ensure the session pipeline exists. Offer a `ChannelInput` carrying the content, the supplied `MessageSource`, and `AckTarget = Sender` into the session pipeline (via the existing `SignalRSessionActor` bridge if one is materialized, or directly into the pipeline input queue if not). **Do NOT reply to the Ask directly on the happy path** — the session's `TryReplyAck` propagates `CommandAck` back via `AckTarget`. Reply `CommandNack` directly only on offer failure. Skip any inbound ACL — the provenance flags indicate a trusted delivery.
- [ ] 3.7 **SignalR side**: verify the "no client connected" path works without extra code. When `SessionRegistry._connections` has no connection for the target session, the turn should still be accepted into the session pipeline; streaming output is dropped per the existing `Source.ActorRef` `OverflowStrategy.DropHead` behavior; the session's `TryReplyAck` still fires and flows back to `AckTarget`; the execution child's Ask completes with `CommandAck`; `TurnRecorded` persists normally. If any of this needs new plumbing to work, add it.
- [ ] 3.8 Unit tests on `SlackGatewayActor` (TestKit): `DeliverTrustedSessionTurn` for a thread with an already-live binding routes correctly; `DeliverTrustedSessionTurn` for a thread with no existing binding triggers lookup-or-create and succeeds; two parallel `DeliverTrustedSessionTurn` calls produce exactly one binding actor; `DeliverTrustedSessionTurn` does NOT call `SlackAclPolicy.EvaluateInbound`.
- [ ] 3.9 Unit test on `SlackThreadBindingActor`: `SlackTrustedInbound` with a mismatching session id is rejected; matching `SlackTrustedInbound` results in a `ChannelInput` offered to the pipeline with the supplied `AckTarget` preserved.

## 5. ReminderExecutionActor Mode B dispatch + envelope ack gating

- [ ] 5.1 In `ReminderExecutionActor.InitializeAsync`, split by `_definition.SessionId` presence. Mode A path remains exactly as today. Mode B path is new.
- [ ] 5.2 Mode B: build a `MessageSource` from stored reminder metadata: `ChannelType = _definition.OriginChannelType`, `SenderId = "reminder-system"`, `ReminderId = $"{_definition.Id}:{_dispatchedAt.ToUnixTimeMilliseconds()}"`, `Audience = _definition.Audience.Value`, `Boundary = SecurityPolicyDefaults.LocalDaemonBoundary`, `Principal = VerifiedAutomation`, `Provenance = { SourceKind = "reminder", TransportAuthenticity = LocalProcess, PayloadTaint = Trusted }`.
- [ ] 5.3 Mode B dispatch: switch on `_definition.OriginChannelType`. For `ChannelType.Slack`, resolve `SlackGatewayActor` via `IRequiredActor<SlackGatewayActorKey>` and `Ask<CommandAck>` it with a `DeliverTrustedSessionTurn`. For `ChannelType.Tui` or `ChannelType.SignalR`, resolve `SignalRGatewayActor` via `IRequiredActor<SignalRGatewayActorKey>` (already exists in `src/Netclaw.Daemon/Gateway/`) and `Ask<CommandAck>` it with the same `DeliverTrustedSessionTurn` message. For any other `OriginChannelType` (Headless, Webhook, Reminder, null), fail the reminder execution immediately with a "no Mode B gateway for channel type X" error — these should have been rejected at set_reminder time but fail loud if one slips through.
- [ ] 5.4 Define the `SlackGatewayActorKey` marker class in a location accessible from `Netclaw.Actors` without a backward dependency on `Netclaw.Channels.Slack`. Slack channel registers its gateway against this key at DI setup time. `SignalRGatewayActorKey` already exists; reuse it. If either channel isn't loaded, `IRequiredActor` resolution fails fast — acceptable because a reminder persisted with an `OriginChannelType` whose channel is disabled cannot be set in the first place (the tool's set-time gateway check will reject it).
- [ ] 5.5 Update `SetReminderTool` to validate `OriginChannelType` at set time against the set of channels with registered Mode B gateways. If the current `context.ChannelType` has no Mode B gateway (e.g., headless, webhook), return a fail-loud error from the tool instead of persisting a reminder that will fail at fire time.
- [ ] 5.6 Mode B: at execution actor startup, acquire `IReminderClient` via `ReminderClientExtension.Get(Context.System)` and store it in a `_client` field. Store the `ReminderEnvelope` passed in from the manager.
- [ ] 5.7 Mode B: on `CommandAck` from the gateway `Ask<CommandAck>(DeliverTrustedSessionTurn)`, call `await _client.AckAsync(_envelope)` (inside an `async` handler, or via `PipeTo(Self)` / `RunTask` per existing execution-actor conventions). Inspect the `ReminderAckResponse.ResponseCode` and log a warning on any non-`Success` value (but still treat the execution as succeeded — the library handles its own retry behavior). Then tell `Context.Parent` a `ReminderExecutionCompleted(success=true)` for bookkeeping (failure counters, history), and `Context.Stop(Self)`.
- [ ] 5.8 Mode B: on `CommandNack`, Ask timeout, gateway transport failure, or unknown exception, do NOT call `_client.AckAsync`. Tell `Context.Parent` a `ReminderExecutionCompleted(success=false)` with an error message. Akka.Reminders' built-in `AckTimeout` / `ProcessAckTimeouts` / `MaxDeliveryAttempts` machinery will redeliver. Log `reminder_mode_b_timeout` or `reminder_mode_b_session_nack` appropriately with turn and reminder identifiers.
- [ ] 5.9 Rewire `ReminderManagerActor.HandleReminderFiredAsync` for Mode B: create the execution child and pass the envelope explicitly (constructor arg or initial message). Do NOT call `_client.AckAsync(envelope)` in the manager for Mode B envelopes — the child handles it after the target session has accepted the turn. Mode A and orphan/disabled paths (lines 424, 433, 455) continue to call `_client.AckAsync(envelope)` eagerly as today.
