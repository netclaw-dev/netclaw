## Problem

In a multi-platform build, `ARG`s declared **after** `FROM` are not per-platform — buildx resolves them to their default value for all platforms.

This meant both `amd64` and `arm64` manifest entries contained the same amd64-linked binary, causing Rosetta crashes on Apple Silicon with exit code 133.

## Root Cause

```dockerfile
# BROKEN: TARGETARCH is invisible to multi-platform resolution
FROM ubuntu:24.04

ARG TARGETARCH=amd64  # ← After FROM, always defaults to amd64
```

## Fix

Move `ARG TARGETARCH` to before `FROM` so buildx injects the correct value per-platform:

```dockerfile
ARG TARGETARCH=amd64  # ← Before FROM, buildx sets this per-platform
ARG NETCLAW_VERSION=unknown

FROM ubuntu:24.04
```

This ensures `COPY publish/cli-${TARGETARCH}/netclaw` selects the right binary for each architecture.

## Smoke Test Added

Added a multi-arch digest verification step to `validate_docker_image.yml` (push-only, not on PRs since multi-arch `--load` needs containerd) that:

1. Builds both platforms via `docker buildx build --platform linux/amd64,linux/arm64 --load`
2. Extracts per-platform digests from the manifest list
3. Fails if amd64 and arm64 have the same digest

This catches the #1091 class of bug in CI going forward.
