Start with a prompt that steers active work

Input admission means that the actor records a prompt before it acknowledges receipt. Pull means that the actor adds that prompt to model input.

The current dev branch owns durable input admission and replay. The old prototype adds separate queue receipts and display counters.

Current prototype: several owners

Actor: InputAdmitted → buffer → model input
Actor: emit queued/pulled receipts from that buffer
ViewModel: retain IDs and a legacy queue counter
Page: retain another list of prompt previews
TurnCompleted: clear legacy display counters

Proposed: derive display state from receipts

send(text, stableSourceMessageId)
  → show local state: Sending
actor persists InputAdmitted → acknowledge → show Queued
actor drains ALL eligible prompts in FIFO order
  → emit one correlated Pulled receipt for that batch
client removes only those IDs from the Queue Shelf
  → add one "Pulled by agent" row to the Reply Block

This schematic pseudocode omits existing policy gates and replay guards. Those gates remain before the affected operations.

A pull can occur between tool-loop steps. The client must not wait for TurnCompleted or dispatch one prompt per turn.

During reconnect, the client retries the same source identity. The actor must not create another admitted input or another model action.

Goals, in priority order

  1. User control. Keep the Composer available during agent work. Show every queued prompt and the exact batch that the agent pulls.
  2. Readable conversation. Use clear speaker labels, whitespace, and quiet prose. Place all tool and sub-agent activity inside the relevant Reply Block.
  3. Useful live feedback. Stream text immediately. Show real tool progress, rationale, parallel activity, and provider-supplied thought or token data.
  4. Native terminal behavior. Preserve terminal scrollback, search, selection, and copy. Do not virtualize settled history again.
  5. Safe decisions. Show one approval at a time. Keep the current daemon policy, request identities, scope, and outcomes authoritative.
  6. Low review burden. Supply headless proof and local visual checkpoints. Do not leave the user with a large manual QA list.

Preserve Shift+Enter, prompt recall, draft restoration, Esc x2 clear, and Ctrl+O detail.

Region names and behavior

A display Turn contains a request, any prompts that steer it, and one Reply Block. It does not create a new actor lifecycle.

A Reply Passage groups prose and work from one model step. Model prose between tool batches creates another passage in the same block.

RegionMotion and lifetime
TranscriptImmutable settled content in the primary buffer. No border, rail, spinner, or recurring divider.
Reply Block / Reply PassageText appears with each delta. The active viewport permits explicit scroll and tail follow. Settlement prints each block once.
Work TraceEach active call has a stable row and local spinner. Safe progress text updates that row. Results remain as compact receipts.
Decision SheetOne approval owns input. Remaining requests wait in order. Ctrl+O preserves the selection. The outcome removes only its request.
Queue ShelfEach prompt stays visible until its correlated pull. A short terminal uses a bounded shelf with access to every prompt, not count-only overflow.
Session StripThe live bottom area retains session, model, context, and connection state. Native scrollback can move the whole live area out of view.
ComposerAvailable during model and tool work. An approval temporarily owns input. The draft survives that transition.
Pulse LineReserve a 12-cell left slot. Only the dots in Thinking. / Thinking.. / Thinking... change. Key hints stay stationary.
InspectorTemporary detail and semantic copy. On exit, restore the draft, selection, terminal modes, and live state.

Use normal foreground for prose, one identity accent, and muted metadata. Reserve amber for decisions and red for failures.

Success uses a label or symbol, not a field of green text. Use at most three emphasis colors within one region.

Use one blank line between speakers and settled turns. Nest work with indentation. Do not add a horizontal line between every block.

Keep rejected rationale calls visible. Use the canonical result failure code. Do not imply that a rejected request ran a tool.
