2. Deferred: renewable allowances

The runtime must enforce the boundary even if the child never requests renewal. A voluntary request alone provides no control.

The review owner considers retained receipts and task evidence. A new rationale, timestamp, or unrelated file cannot automatically earn renewal.

Healthy tasks can receive successive renewals for days. Total age, token use, and call count do not automatically terminate the task.

A live child that waits for renewal needs another lifecycle state and a typed request/response contract. This is not accepted first scope.

Why this can be safe, and what remains uncertain

A review boundary keeps an unresolved episode visible. It does not grant more tool authority or erase previous failures.

Test an absent request, delayed review, stale approval, reflexive renewal, valid pagination, and a real repair.

Keep status and cancellation available during review. Define a visible outcome when the reviewer fails.

Automatic approval can permit an unlimited loop. Review frequency and approval evidence remain open decisions.

3. Deferred: supervisor assessment

The parent session actor owns lifecycle and authority. A separate model assessor can review evidence and recommend an action.

Those roles are different. A model recommendation cannot bypass exact protection, approval, or path policy.

Give the assessor the objective, bounded episode facts, prior corrections, known repairs, and uncertainty. Do not rely only on the worker's summary.

Use an offline advisory experiment first. A live supervisor needs an explicit operation deadline and decision application contract.

Runtime invariants remain effective even when the assessor approves a prohibited action. Retained receipts permit an independent review.

Test an assessor that agrees with a false completion claim. Also test a false pause during useful repair and a stalled assessment.

A different model does not prove independence or correctness. A supervisor can itself enter a loop.

// Both LlmSessionActor and SubAgentActor use this same detector contract.
OnModelToolCalls(IReadOnlyList<FunctionCallContent> calls):
    registry.CanonicalizeToolCalls(calls)
    PreparedToolCycleBatch batch =
        ToolCycleSignatureFactory.Prepare(calls, executor)

    // Keep this state inside TurnStateTracker.
    // The round identifies model feedback, not a task-lifetime allowance.
    round = tracker.Proposed_BeginFeedbackRound()
    groups = batch.Calls.GroupBy(c => (c.ToolName, c.ArgumentsHash))

    // Evaluate the whole response before any tool can start.
    decisions = groups.Map(group =>
        tracker.Proposed_EvaluateCallGroup(group, round, repeatRules))
    decisions = Proposed_CombineWithExistingExactCycleRule(batch, decisions)

    if decisions.Any(d => d.Kind == ToolCycleDecisionKind.Stop):
        Proposed_RejectNewDispatch()
        // The terminal candidate is unadmitted. Do not append orphan calls.
        Proposed_SettlePartialWithoutModel(
            SubAgentOutcomeReason.ToolCycleStopped,
            retainedEvidence)
        return

    Proposed_PersistAdmissionAndAssistantCalls(calls, decisions)

    foreach group in groups:
        if decisions[group].Kind == ToolCycleDecisionKind.Correct:
            foreach PreparedToolCycleCall call in group:
                receipt = new ToolInvocationReceipt.Correction(
                    ToolRemediationCode.BreakToolCycle)
                Proposed_PairCorrectionResult(call.CallId, receipt)
            tracker.Proposed_RecordOneRefusedRound(group, round)
            continue

        // Use the existing execution path, not a direct tool invocation.
        // Validation, authorization, approval, redaction, and timeouts remain.
        Proposed_DispatchThroughExistingPipeline(group, calls)

    // Supply one result per call before the next model request.
    // A approval retry remains inside the same authorization attempt.
    // It does not create another model feedback round.
