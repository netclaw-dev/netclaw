The runtime workflow

1. Page: translate a key or selected option into a view-model action.
2. View-model: validate page input, set page state, and call the client.
3. DaemonClient: create a typed command and submit it before the first await.
4. ChatClientActor: select the session, order commands, and start at most one transport operation.
5. Transport adapter: map the local protocol to SignalR and return a typed result.
6. Daemon: check authority, admit text to the journal, and then acknowledge admission.

Response path: transport callback → typed client event → event pump → view-model InvokeAsync → page state and terminal display.

Within one UI loop action, apply page state first, publish transcript output second, and request redraw last.

Control results return through actor messages. Raw transcript output need not pass through the lifecycle actor.

The event pump prevents subscriber code from occupying the actor. The Termina loop serializes page-state and terminal-node changes.

The concrete change

A user presses Enter and then Ctrl+Q. The client must resolve daemon admission before it closes the transport.

Admission means that the daemon journal stores the text input. It does not mean that the model finished a turn.

Pinned baseline client, abbreviated

SubmitAsync(text):
  if not ready or disconnected:
    pending.Enqueue(text)
    start ConnectUntilReadyAsync()
  else:
    await SendAsync(text)

Connected callback:
  start EnsureSessionAndFlushAsync()

ConnectUntilReadyAsync():
  connect; acquire setup gate; bind; flush

RequestAppShutdown():
  Shutdown()

Replacement client, schematic

Receive(Submit(text)):
  pending.Enqueue(text)
  advance the current behavior

Unattached + pending input:
  Become(Operating)
  bindTask.PipeTo(Self)

Attached + pending input:
  Become(Operating)
  sendTask.PipeTo(Self)

Receive(Close):
  reject later submissions
  continue admission until done or deadline
  reply ChatCloseReceipt; Become(Closed)

Host disposal:
  terminate the local ActorSystem

The proposed example omits transport guards, identity mapping, cancellation, and event publication. Those steps remain required.

One actor will replace both the client command loop and the view model lifecycle paths.

The daemon fix will make the successful text RPC response depend on the existing journal acknowledgment.

CLI actor → existing SignalR SendMessage method
Registry → validate attachment, authenticated identity, and ingress → gateway actor
Gateway → existing ChannelInput.AckTarget → real channel pipeline → LlmSessionActor
Session → persist InputAdmitted → existing CommandAck → successful hub response
CLI actor → mark admission confirmed → permit normal close

The shared acknowledgment type retains its other meanings. This contract applies to the text-only SignalR SendMessage route.

Failure results

Connection or attachment failure before an input RPC leaves the input safe to retry.

A confirmed daemon rejection ends that input attempt and produces a transcript notice.

An interrupted RPC produces delivery unconfirmed. The client must not automatically resend that input.

This intentionally removes the current ready-path automatic resend after an uncertain send failure.

Behavior and asynchronous work

Behavior Switching and Receive Timeouts explains that Become replaces the current message handlers.

It also describes ReceiveTimeout as a period without relevant activity. Activity resets that period.

For this client, every behavior must retain the control handlers it needs. The close deadline must stay fixed despite later events.

Actors and Async / Await distinguishes ReceiveAsync from PipeTo.

ReceiveAsync suspends other user messages until its task completes. PipeTo sends the task result back as a message.

For this client, connect, bind, and send use PipeTo so close and transport-drop commands remain available.

Capture task inputs before dispatch. Task continuations must not mutate actor state or read the actor's current Sender or Context.

Deferred input, timer lifetime, and message data

Sagas, Message Stashing, and IWithTimers explains how a stash preserves messages and their senders until a behavior can accept them.

The lesson also describes actor timers that cancel on actor stop or restart.

This client retains one explicit input queue because close must inspect each input's delivery outcome. A second stash must not duplicate that queue.

Close, transport-drop, and cancellation commands must execute promptly. They must not wait in a catch-all stash.

Use IWithTimers and TestScheduler for elapsed deadlines. Retain TimeProvider for UTC timestamps; it does not drive actor timers.

Effective Actor Messaging separates commands, events, queries, and acknowledgments. It requires immutable message data.
